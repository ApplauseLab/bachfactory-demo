# Verify user authentication with better-auth

## Intent

The issue asks for better-auth email/password authentication across the todo stack: server auth routes with SQLite sessions, protected `/todos`, sign-up/sign-in views, a session-aware header, and logout. Inspection shows this exact slice already shipped to `main` with the prior item (plan `01a047cb-27cf-7aaa-8928-da62ab1ca2d6`, squash-merged as commit `e182ed0`, PR #7): `apps/server/src/auth.ts`, `apps/server/src/app.ts` auth routing and session gate, `apps/web/src/AuthForm.tsx`, the session-aware `AccountHeader` with sign-out, colocated auth tests, and the paced `e2e/todo-auth.spec.ts` all exist. This item therefore becomes the smallest honest slice: prove every requirement of the issue against the shipped stack, close any real gap the proof uncovers, and attach this item's own narrated demo of the authed flow.
