# Build the full-stack todo application

## Intent

Bootstrap the empty Bun workspace with a SQLite-backed TypeScript todo API and a React/Vite client that exercise the complete todo lifecycle together. The slice will provide route and client-layer tests, production builds for both apps, and a narrated browser demo proving the locally deployed stack works end to end.

## Plan Notes

- The issue and item PR have no prior human comments, so there are no feedback corrections to incorporate.
- Use `PATCH /todos/:id` for updates, accepting a non-empty `title`, a boolean `done`, or both, and reject payloads with neither supported field. Allow CORS from `WEB_ORIGIN`, defaulting to `http://localhost:5173`, so local Vite development works without broad wildcard access.

## Tasks

- [ ] Add `apps/server/package.json` and TypeScript configuration with the requested `dev`, `start`, `test`, and Bun-targeted `build` scripts.
- [ ] Add the `apps/server/src` database and HTTP modules: create the requested SQLite schema on boot, map stored integer completion values to JSON booleans, expose `GET /health` and full `/todos` CRUD, validate create/update bodies, return 404s for unknown IDs, and apply web-origin CORS headers.
- [ ] Add colocated Bun tests under `apps/server/src` that use an isolated temporary/in-memory database and cover health, list, get, create, title/completion updates, delete, CORS, malformed or invalid payloads, and unknown IDs without writing the production database.
- [ ] Add `apps/web/package.json`, Vite/TypeScript configuration, and the requested `dev`, `build`, and `test` scripts for a React SPA.
- [ ] Add a typed `apps/web/src` API client using `import.meta.env.VITE_API_URL ?? "http://localhost:3000"`, plus colocated Bun tests for request paths and methods, response decoding, and surfaced API failures.
- [ ] Build the `apps/web/src` interface and styling for loading and error states, listing todos, adding a non-empty todo, toggling completion, and deleting a todo in a responsive, desktop-first dark theme.
- [ ] Update workspace dependency metadata and ignore generated server data, build output, demo media, and other runtime artifacts while retaining source and the published demo URL.
- [ ] Add a paced Playwright flow under `e2e/` that starts from deterministic data and demonstrates loading the app, adding a todo, toggling it complete, and deleting it; record, narrate, verify, and publish the resulting demo per the narrated-demo skill.
- [ ] Run both app builds and `bach run group/ci`, then boot the built stack locally and verify the web client can perform CRUD against the API.

## Acceptance

- [ ] unit tests green (`bach run group/ci`)
- [ ] narrated demo video produced per the skill and attached to the PR
- [ ] `GET /health` returns `{ "status": "ok" }` on `PORT` (default 3000), and every `/todos` CRUD route persists through the requested SQLite schema
- [ ] invalid create/update payloads return 400, unknown todo IDs return 404, and CORS permits the configured web client origin
- [ ] the React client uses the configured API base and supports list, add, toggle, and delete in a clean responsive dark UI
- [ ] both apps build successfully, and the local deployment serves the API and web build together
