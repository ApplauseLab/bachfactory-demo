# Build the full-stack todo application

## Intent

Bootstrap the empty Bun workspace with a SQLite-backed TypeScript todo API and a React/Vite client that support the complete todo lifecycle together. Cover both app boundaries with tests and production builds, then prove the locally deployed stack through a narrated browser demo published to S3.

## Plan Notes

- The intake issue was requeued after repository references were pinned and the `.opencode-snitch-off` marker was pre-seeded. Preserve those baseline files and use the configured narration workflow without changing factory-owned files.
- The prior item PR was approved for implementation and reported 19 unit tests, one end-to-end test, and successful builds, but its public demo upload was blocked because `DARK_FACTORY_S3_BUCKET` was unset. Treat public S3 publication and a usable PR URL as required completion criteria, and report a blocker rather than claiming the attachment is complete if credentials or configuration remain unavailable.
- Use `PATCH /todos/:id` for updates, accepting a non-empty `title`, a boolean `done`, or both, and reject payloads with neither supported field. Allow CORS from `WEB_ORIGIN`, defaulting to `http://localhost:5173`, rather than allowing every origin.

## Tasks

- [ ] Add `apps/server/package.json` and TypeScript configuration with `dev`, `start`, `test`, and Bun-targeted `build` scripts.
- [ ] Implement `apps/server/src/index.ts` and supporting modules to initialize the requested SQLite schema, map integer completion values to JSON booleans, listen on `PORT` (default 3000), and expose `GET /health` plus list, get, create, patch, and delete `/todos` routes with configured CORS.
- [ ] Add colocated Bun server tests using an isolated temporary or in-memory database that cover every route, title and completion updates, malformed and invalid payloads, configured CORS, and unknown IDs without writing the production database.
- [ ] Add `apps/web/package.json`, Vite and TypeScript configuration, and the requested `dev`, `build`, and `test` scripts for a React SPA.
- [ ] Add a typed web API client using `import.meta.env.VITE_API_URL ?? "http://localhost:3000"`, with colocated tests for paths, methods, response decoding, and surfaced API failures.
- [ ] Build a responsive, desktop-first dark interface with loading and error states and controls to list, add, toggle, and delete todos.
- [ ] Update workspace dependency metadata and ignore generated database, build, test, and local demo artifacts without removing the pre-seeded Snitch marker or changing factory-owned configuration.
- [ ] Add a paced Playwright flow under `e2e/` with deterministic data that demonstrates loading the app, adding a todo, toggling it complete, and deleting it against the local deployment.
- [ ] Preflight the narrated-demo and S3 settings, record and verify the narrated MP4 per the skill, upload it publicly, and add its accessible URL to the item PR; surface missing upload configuration as a blocker.
- [ ] Run both production builds and `bach run group/ci`, then boot the built stack locally and verify the browser flow against the API.

## Acceptance

- [ ] unit tests green (`bach run group/ci`)
- [ ] narrated demo video produced per the skill, published to S3, and attached to the PR with a publicly accessible URL
- [ ] `GET /health` returns `{ "status": "ok" }`, and every `/todos` CRUD route persists through the requested SQLite schema
- [ ] invalid create or update payloads return 400, unknown todo IDs return 404, and CORS permits the configured web client origin
- [ ] the React client uses the configured API base and supports list, add, toggle, and delete in a clean responsive dark UI
- [ ] both apps build successfully, and the local deployment serves the API and web build together
