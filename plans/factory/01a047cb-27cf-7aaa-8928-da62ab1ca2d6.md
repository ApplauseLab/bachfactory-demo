# Add better-auth email/password to the todo stack

## Intent

Add authentication on top of the shipped todo stack using
[better-auth](https://www.better-auth.com). The Bun server gains better-auth
email/password with SQLite-backed sessions and auth routes, and `/todos`
becomes session-protected; the React SPA gains sign-up/sign-in views, a
session-aware header, and logout. Proven by green `group/ci` tests and a
narrated demo of the authenticated flow.

## Plan Notes

- Feedback mining — issue #6 has no comments; prior item PRs #2–#5 carry no
  human `/deny` corrections (approvals and agent feed only). PR #5's demo
  upload to `cnicolov-todo-dark-factory.s3` succeeded, so the S3 demo path is
  configured; keep the honest-`blocked` rule if that changes.
- better-auth is wired to the **same** SQLite database as todos
  (`bun:sqlite` handle passed to `betterAuth({ database })` per its
  documented Bun integration; auth tables are created by better-auth). The
  `todos` schema is unchanged; tests keep using an isolated in-memory db.
- Session cookie crosses `http://localhost:5173 → http://localhost:3000`:
  configure better-auth cross-origin cookies (`SameSite=None; Secure`,
  `trustedOrigins` from `WEB_ORIGIN`) — Chromium (and Playwright's browser)
  waive the Secure requirement on localhost. Fallback if a browser rejects
  it: serve the built SPA from the server origin (same-origin cookies) —
  record which path shipped.
- Protected surface is exactly `/todos*` (all methods → 401 JSON
  `{"error":"unauthorized"}` without a valid session). `/health` and
  `/api/auth/*` stay public; CORS gains `access-control-allow-credentials`.
- `BETTER_AUTH_SECRET` comes from the environment; tests pin a fixed value
  and local deploys use a dev fallback — no real secrets are committed.
- The existing `e2e/todo-full-stack.spec.ts` seeds through unauthenticated
  API calls, which will 401 — its seed/drain helpers must sign in a test
  user via the auth API first so the shipped demo spec keeps passing.
